القسم الأول: الرؤية العامة والبنية التحتية (Tech Stack & Infrastructure)
نحن نبني منصة تعليمية احترافية للدروس الأونلاين (LMS) مخصصة للسوق المصري والعربي، مصممة لتحمل آلاف الطلاب المتزامنين في نفس الثانية، بأعلى معايير الأمان، وبأقل استهلاك ممكن لطلبات السيرفر وقاعدة البيانات (Near-Zero Unnecessary Requests).
إطار العمل (Framework): Next.js (App Router + TypeScript + Tailwind CSS).
بيئة التشغيل والاستضافة النهائية (Hosting & Runtime): Cloudflare Pages / Workers باستخدام محول @opennextjs/cloudflare (بيئة Edge Runtime).
قاعدة البيانات والمصادقة (Database & Auth): Supabase (PostgreSQL) مع تفعيل:
Row Level Security (RLS) الصارم على كافة الجداول.
PostgreSQL Functions (RPC) لتجميع استعلامات كل شاشة في Request واحد.
PostgreSQL Triggers لسجل مراقبة المساعدين (Audit Logs) وتحديث الإحصائيات داخلياً بدون طلبات إضافية.
Supabase Realtime Presence (WebSockets) لمعرفة عدد الطلاب المتصلين حالياً (Online Users) بدون استهلاك DB Queries.
Supavisor Transaction Pooler (Port 6543) لمنع استنفاد الاتصالات وقت الذروة.
تخزين الفيديوهات والملفات والصور (Object Storage): Cloudflare R2 (يتميز بـ Zero Egress Fees)، ويتم التعامل معه على السيرفر حصرياً عبر مكتبة aws4fetch الخفيفة المتوافقة مع Cloudflare Edge Runtime (يُمنع استخدام @aws-sdk/client-s3 الثقيلة غير المتوافقة مع الـ Edge).

القسم الثاني: القواعد المعمارية الصارمة ("مكعبات الليجو" وهندسة تقليل الـ Requests)
1. هيكلة الكود بنظام المكعبات (Feature-Based Modular Lego Architecture)
يُقسم المشروع بصرامة إلى مكعبات مستقلة داخل src/features/، ويُمنع أن يتجاوز أي ملف كود 250 سطراً:
src/features/auth/ (التسجيل ذو الـ 3 خطوات، الدخول، والأمان).
src/features/courses/ (شجرة الكورسات، الكورسات الشاملة، والغلق التسلسلي).
src/features/video-player/ (مشغل الـ HLS المتوافق مع الآيفون والأندرويد والـ Watermark).
src/features/exams/ (الكويزات، الواجبات، التايمر، التصحيح، وبنك "غلطاتي").
src/features/payments/ (أكواد السنتر، وتحويلات فودافون كاش / إنستا باي).
src/features/forum/ (المنتدى الخاص والعام والرد الصوتي Voice Note).
src/features/notifications/ (جرس الإشعارات ولوحة إشعارات الأدمن).
src/features/admin-rbac/ (صلاحيات المساعدين، سجل المراقبة، وسلة المحذوفات).
src/lib/server/ (ملفات محمية بـ import 'server-only' لعزل مفاتيح R2_SECRET_ACCESS_KEY وSUPABASE_SERVICE_ROLE_KEY عن المتصفح نهائياً).
قانون عدم التشابك (No Circular Dependencies & No Barrel Files):
يُمنع منعاً باتاً أن يستورد مكعب داخلي (features/A) من مكعب آخر (features/B) مباشرة. يتم التجميع فقط داخل صفحات src/app/ أو عبر دوال قاعدة البيانات (RPC).
يُمنع استخدام ملفات index.ts التجميعية (Barrel Files) للحفاظ على سرعة التحميل (Tree-shaking).
يُحاط كل مكعب في الواجهة بحائط عزل أخطاء (Granular Error Boundary) لمنع سقوط الصفحة بالكامل إذا حدث خطأ عارض في متصفح قديم.
2. القواعد الذهبية لمنع انفجار الـ Requests (Anti-Request Waterfall Rules)
منع الـ useEffect Waterfalls: يُمنع تقسيم الشاشة الواحدة إلى عدة مكونات يرسل كل منها طلب SELECT منفصل عند فتح الصفحة (ممنوع إرسال 15-20 Request عند فتح الداشبورد!).
قاعدة الـ Request الواحد لكل شاشة: يتم جلب بيانات الشاشات المركبة (مثل داشبورد الطالب أو شجرة الكورس بالأقفال) عبر استدعاء دالة Supabase RPC واحدة فقط ترجع JSON مجمع، أو عبر Next.js Server Components.
إيقاف التحميل المسبق العشوائي: كافة روابط <Link> في القوائم الجانبية والعلوية يجب أن تحمل الخاصية prefetch={false} لمنع إرسال طلبات خلفية لصفحات لم يضغط عليها المستخدم.
إيقاف إعادة الجلب التلقائي عند التركيز: في إعدادات الكاش (React Query / SWR)، يجب ضبط refetchOnWindowFocus: false وstaleTime: 5 minutes.
البحث المؤجل ومنع التكرار: أي خانة بحث (عند الأدمن أو الطالب) تُطبق Debounce (500ms)، وأي زر إرسال (Submit) يُقفل فوراً (disabled + loading state) عند أول ضغطة لمنع الطلبات المكررة.

القسم الثالث: المواصفات التفصيلية لجميع أنظمة المنصة
1. نظام الحسابات، التسجيل، والأمان (Auth & Security)
التسجيل بدون تكلفة SMS (Virtual Email Trick): يسجل الطالب ويدخل برقم الهاتف وكلمة السر فقط. في الخلفية، يتم تحويل رقم الهاتف المُنقى إلى بريد افتراضي داخلي بصيغة 010xxxxxxxx@student.platform.local للاستفادة الكاملة من Supabase Auth & JWT & RLS مجاناً.
مراحل التسجيل الـ 3 للطالب:
الخطوة 1: الاسم (خانة أو خانتين) + رقم هاتف الطالب.
الخطوة 2: الصف الدراسي + نوع التعليم + المحافظة + النوع + رقم هاتف ولي الأمر (شرط إجباري في الفرونت إند والداتابيز CHECK (phone <> parent_phone) أن يختلف عن رقم الطالب).
الخطوة 3: كلمة السر وتأكيدها.
بعد التسجيل: يُفتح الحساب مبدئياً فوراً حتى لا يتعطل الطالب، وتظهر له رسالة بأن بياناته قيد المراجعة خلال 24-48 ساعة، ويظهر في قائمة المراجعة عند الأدمن.
تنظيف المدخلات والـ Copy/Paste: يُسمح بالـ Copy & Paste في جميع الخانات (بما فيها الهاتف والباسورد والأكواد). يقوم الكود تلقائياً بتحويل الأرقام العربية/الهندية (٠١٠...) إلى إنجليزية (010...) وحذف المسافات الزائدة، مع الفلترة بـ Zod ضد أي أكواد خبيثة (XSS / SQLi).
إدارة كلمة السر: الطالب المسجل دخوله يغير كلمته من تاب "الأمان" في "حسابي". الطالب الذي نسي كلمته وهو بالخارج يتواصل مع الدعم الفني، ويملك الأدمن صلاحية تغيير كلمة سر أي طالب مباشرة من لوحة التحكم.
تتبع الأجهزة والإحصائيات: تُسجل بيانات الدخول (نوع الجهاز، اسمه، نظام التشغيل، المتصفح، آخر نشاط، وعدد مرات الخروج اليومية والأسبوعية) في جدول login_sessions وتُعرض للطالب كإحصائيات فقط بدون قفل الحساب.
حماية الـ Middleware: يفحص ملف middleware.ts صلاحية الـ JWT محلياً بدون إرسال طلبات لقاعدة البيانات، مع استثناء كافة ملفات الـ Static والصور في الـ Matcher.
2. هيكلة الكورسات، الكورس الشامل، والغلق التسلسلي (Course Engine & Smart Locking)
تقسيم ديناميكي حر التسمية: الأدمن يتحكم في المسميات بحرية (أبواب / أسابيع / وحدات -> محاضرات -> عناصر المحاضرة: فيديو شرح، ملف PDF، كويز، واجب، فيديو حل الكويز، ملف حل الكويز، فيديو حل الواجب، ملف حل الواجب).
نظام الكورس الشامل / الباقات (Unified Bundle View):
إذا اشترك الطالب في "كورس شامل" يضم عدة أبواب، يظهر له في صفحة "كورساتي" كارت كورس واحد فقط (الكورس الشامل) وبداخله الأبواب مرتبة حتى لا يتشتت بظهور 3 كورسات منفصلة.
في لوحة التحكم، يربط المدرس الأبواب الموجودة مسبقاً بالكورس الشامل عبر جدول ربط (course_modules_map) دون إعادة رفع الفيديوهات أو الامتحانات مرتين.
قواعد الإغلاق التسلسلي الصارمة (Sequential Locking):
المحاضرة الأولى: مفتوحة تلقائياً للمشتركين.
المحاضرة الثانية وما بعدها: مقفولة بـ 🔒، ولا تفتح إلا إذا سلم الطالب كويز وواجب المحاضرة السابقة في الترتيب داخل الكورس وحقق نسبة نجاح 50% على الأقل (قابلة للتعديل من الأدمن لكل محاضرة).
فيديوهات وملفات الحل: تظهر تحت الكويز أو الواجب مباشرة ولكن مقفولة بـ 🔒 (unlock_after_exam_id)، وتفتح فوراً بمجرد تسليم الطالب للكويز أو الواجب.
الاستثناء اليدوي والجدولة: يملك الأدمن زر "فتح استثنائي يدوي" لفتح محاضرة لطالب معين، وخاصية جدولة فتح المحاضرة في تاريخ ووقت محدد (publish_at بتوقيت Africa/Cairo).
3. مشغل الفيديو الاحترافي والبث (Cross-Platform HLS Video Player)
صيغة الفيديو الواحدة: يقوم الأدمن بتجهيز الفيديو بأداة خارجية تحوله إلى فولدر HLS (.m3u8 + .ts segments) ويرفعه كنسخة واحدة إلى Cloudflare R2 عبر Presigned URLs بصلاحية 4 ساعات (14400s) مع خاصية Auto-Retry للقطع التي تفشل أثناء الرفع.
التشغيل السلس على الآيفون والأندرويد والكمبيوتر:
الكود يفحص المتصفح: إذا كان يدعم hls.js (أندرويد وكمبيوتر) يشغلها مع ضبط backBufferLength: 60 وmaxBufferHole: 0.5 لمنع التعليق عند التقديم والتأخير أو التسريع.
إذا كان الجهاز آيفون (iOS Safari)، يمرر رابط الـ .m3u8 مباشرة لتاج <video> الأصلي (Native HLS) بدون hls.js، مع استخدام webkitEnterFullscreen() لزرار التكبير وخاصية playsInline.
تناسق الأزرار واتجاه الشريط: يُجبر مشغل الفيديو على dir="ltr" حتى يعمل شريط التقديم من اليسار لليمين بشكل صحيح، وتُجمع خيارات السرعة والجودة في قائمة إعدادات متجاوبة على شاشات الموبايل الصغيرة لمنع تداخل الأزرار.
حفظ مكان التوقف بدون Requests: يتم تحديث الثانية الحالية في localStorage كل 3 ثواني بعملية استبدال (Overwrite لنفس المفتاح بدون تراكم وبدون إرسال أي Request للسيرفر)، بحيث إذا عمل الطالب Refresh يكمل من نفس الثانية فوراً. لا يُرسل للسيرفر سوى Request واحد عند إتمام المحاضرة.
حماية الفيديو: الـ R2 Bucket خاص (Private) ومحمي بـ Signed Token عبر Cloudflare Worker مع تفعيل الـ CDN Cache، وتظهر علامة مائية متحركة شفافة برقم واسم الطالب داخل المشغل (حتى في وضع الـ Fullscreen).
4. محرك الامتحانات، الواجبات، وبنك "غلطاتي" (Exams & Mistakes Bank)
رفع الأسئلة السريع (Zero-Typing): يرفع الأدمن صورة السؤال شاملة الاختيارات، ويظهر للطالب تحتها 4 أزرار جاهزة فقط: ( أ ) - ( ب ) - ( ج ) - ( د )، ويحدد الأدمن الحرف الصحيح فقط، مع خيار تفعيل الترتيب العشوائي للأسئلة (Question Shuffling).
تأمين الامتحان وتجربة الحل:
عمود الإجابة الصحيحة (correct_option) لا يخرج للفرونت إند أبداً أثناء الامتحان.
التايمر محسوب بوقت السيرفر (started_at) لمنع الغش بتغيير ساعة الجهاز.
حفظ ترتيب الأسئلة العشوائي في assigned_question_ids عند بدء المحاولة حتى لا يتغير ترتيب الأسئلة إذا عمل الطالب Refresh.
حفظ إجابات الطالب لحظياً في localStorage أثناء الحل، وإرسالها في Request واحد فقط عند الضغط على "إنهاء وتسليم" (أو تلقائياً عند انتهاء الوقت).
خريطة أسئلة جانبية (أخضر للمحلول، رمادي لغير المحلول، أصفر للمعلم للمراجعة 🚩) وتنبيه beforeunload لمنع الخروج الخاطئ.
عدد المحاولات مفتوح ليتمكن الطالب من الإعادة إذا حصل على أقل من 50%.
إعادة التصحيح التلقائي (Auto Re-grade): إذا عدل الأدمن الإجابة الصحيحة لسؤال بعد امتحان الطلاب، تقوم دالة في قاعدة البيانات بإعادة تصحيح كافة المحاولات السابقة وتحديث درجات الطلاب وفتح المحاضرات وتحديث بنك "غلطاتي" بضغطة واحدة.
تاب "غلطاتي" في صفحة حسابي: يعرض كافة الأسئلة التي أخطأ فيها الطالب، مع فصل تام بفلترين مستقلين: (أخطاء الكويزات لوحدها) و(أخطاء الواجبات لوحدها).
5. نظام الاشتراكات، الفواتير، وضغط الصور (Payments & Image Pipeline)
أكواد الشحن (كروت السنتر): يولدها الأدمن لكورس محدد، وتُفعل بدالة PostgreSQL محمية بـ FOR UPDATE Row Lock لمنع استخدام نفس الكود من طالبين في نفس الجزء من الثانية (Race Condition).
تحويل فودافون كاش / إنستا باي والتفعيل المؤقت الفوري:
يقرأ الطالب أرقام المحافظ من جدول platform_settings (Read-Only).
يرفع الطالب صورة الإيصال + يكتب الرقم المحول منه ورقم العملية المرجعي (UNIQUE في الداتابيز لمنع التكرار).
التفعيل المؤقت الفوري: يفتح الكورس للطالب فوراً لحين مراجعة الأدمن. إذا رفض الأدمن الإيصال لتلاعبه، يتم سحب صلاحية الكورس وطرده لحظياً عبر Realtime وحظره من ميزة التفعيل الفوري مستقبلاً (instant_activation_banned = true).
مسح الإيصالات تلقائياً: توضع صور الإيصالات في مسار receipts/ على R2 وتُحذف تلقائياً كل 29 يوم عبر Object Lifecycle Rule، مع بقاء سجل الفاتورة النصي في الداتابيز.
ضغط الصور وحماية الباك إند (Backend Rate Limiting):
أي صورة يختارها الطالب أو الأدمن (حتى لو 10MB) يضغطها المتصفح تلقائياً عبر <canvas> إلى صيغة WebP بحجم أقل من 500KB قبل الرفع.
يفرض الباك إند والداتابيز قيوداً صارمة ضد المتلاعبين بالـ API: فحص الـ Magic Bytes، رفض أي صورة أكبر من 500KB، وبحد أقصى 3 صور إيصالات في الساعة، وبحد أقصى 5 أسئلة في المنتدى كل 24 ساعة لكل طالب.
6. واجهات الطالب، المنتدى الصوتي، الإشعارات، ولوحة الأدمن
التصميم والواجهة: اتجاه RTL، وضع ليلي/نهاري بدون وميض (next-themes)، حجم خط الخانات لا يقل عن 16px على الموبايل لمنع الـ Zoom الإجباري على الآيفون، وتنبيه عند فتح الموقع من متصفح فيس بوك/واتساب الداخلي (In-App Browser).
صفحة حسابي (6 تابات): (1) الملف الشخصي والفواتير، (2) الأمان وتاريخ الدخول وتغيير الباسورد، (3) نتائج الامتحانات وعرض الإجابات بالفلتر، (4) نتائج الواجبات، (5) مشاهدات الفيديوهات، (6) غلطاتي (مفصول كويزات / واجبات).
المنتدى: سؤال الطالب يظهر له وحده في "أسئلتي الخاصة"، ويرد المدرس بنص أو صورة أو تسجيل صوتي (Voice Note بصيغة MP4/AAC متوافقة مع iOS Safari وأندرويد)، ويختار المدرس هل يظل خاصاً بالطالب أم يُنشر في المنتدى العام.
الإشعارات: يرسل الأدمن إشعارات مخصصة (للجميع / لصف / لكورس / لطالب). تُتبع قراءة الإشعارات العامة عبر عمود last_notifications_read_at في profiles، ويُحفظ last_notified_id في localStorage لمنع رنين صوت الإشعار مع كل Refresh!
صلاحيات المساعدين وسلة المحذوفات: يحدد المدرس صلاحيات كل مساعد عبر Checkboxes تُحفظ كـ JSONB في الـ JWT وتُحمى بـ RLS. كافة عمليات الحذف للكورسات والامتحانات والطلاب هي حذف آمن (Soft Delete عبر deleted_at) يمكن استرجاعه من "سلة المحذوفات"، مع دعم تصدير كشوف الطلاب لـ Excel بالعربي (UTF-8 BOM CSV) وإرسال تقارير واتساب لولي الأمر.

🧪 القسم الرابع: الاختبارات الهندسية الـ 10 الإجبارية (AI Agent Qualification Exam)
تعليمات الاختبار لك يا أداة الذكاء الاصطناعي: لا تكتب جمل إنشائية عامة مثل "نعم فهمت وسألتزم بذلك". أثبت كفاءتك التقنية الآن بالإجابة على هذه الأسئلة الـ 10 بدقة، واكتب الكود التوضيحي المطلوب لكل سؤال داخل ردك:
اختبار منع انفجار الـ Requests في الداشبورد: اشرح كيف ستبني صفحة "داشبورد الطالب الرئيسية" بحيث تفتح بـ Request واحد فقط بدلاً من إرسال 6 طلبات منفصلة، واكتب شكل استدعاء الدالة والـ Caching الذي ستستخدمه، وكيف ستتعامل مع مكون <Link> في القائمة الجانبية؟
اختبار مشغل الفيديو على الآيفون (iOS Safari) مقابل الأندرويد: اكتب دالة الكود (React/TypeScript snippet) التي ستشغل نفس فولدر الـ HLS (.m3u8) على كل من أندرويد/ويندوز (مع إعدادات الـ Buffer لمنع التعليق عند التقديم والتأخير) وعلى الآيفون، واكتب كود زرار تكبير الشاشة (Fullscreen) الذي يعمل على الآيفون بدون فشل.
اختبار منع التضارب اللحظي في أكواد الشحن (Race Condition): لو أدخل طالبان نفس كود الشحن في نفس الجزء من الثانية، اكتب كود دالة الـ PostgreSQL (plpgsql) التي تمنع استخدام الكود مرتين وتفعل الكورس ذرياً (Atomically).
اختبار حماية الباك إند ضد المتلاعبين بالـ API (الصور والمنتدى): إذا قام طالب يفهم في البرمجة بتخطي واجهة الموقع واستخدم Postman لإرسال 50 سؤالاً في المنتدى أو رفع صور بحجم 10MB، اشرح واكتب المنطق البرمجي في الباك إند/الداتابيز الذي سيوقفه فوراً (قاعدة الـ 5 أسئلة/24 ساعة وقاعدة الـ 3 إيصالات/ساعة).
اختبار التوافق مع Cloudflare Edge Runtime وعزل المفاتيح السرية: لماذا يفشل @aws-sdk/client-s3 غالباً على Cloudflare Edge؟ وما المكتبة البديلة التي سنستخدمها لتوليد رابط رفع مؤقت (Presigned URL بصلاحية 4 ساعات) لـ Cloudflare R2؟ وكيف ستضمن برمجياً استحالة تسرب R2_SECRET_ACCESS_KEY إلى متصفح الطالب؟
اختبار الكورس الشامل (الباقات) والغلق التسلسلي بـ 50%: اشرح كيف ستصمم علاقة الجداول بحيث إذا اشترك الطالب في "الكورس الشامل" يظهر له كورس واحد فقط في صفحته دون أن يضطر المدرس لرفع الفيديوهات مرتين، وكيف ستُحسب حالة القفل 🔒 للمحاضرات ولـ "فيديو حل الكويز/الواجب"؟
اختبار ثبات الامتحان والتايمر وإعادة التصحيح: كيف ستمنع الطالب من الغش بتأخير ساعة هاتفه أثناء الامتحان؟ وكيف ستضمن عدم تغير الترتيب العشوائي للأسئلة إذا عمل الطالب Refresh للصفحة؟ وماذا يحدث في الداتابيز لو عدل المدرس الإجابة الصحيحة لسؤال بعد أن امتحن 200 طالب؟
اختبار الإشعارات الذكية (بدون تضخم الداتابيز وبدون رنين مع الـ Refresh): كيف سنرسل إشعاراً لـ 1000 طالب بسطر واحد فقط في الداتابيز مع معرفة هل قرأه الطالب أم لا؟ وكيف سنمنع تكرار رنين صوت الإشعار في المتصفح كلما عمل الطالب Refresh للصفحة؟
اختبار صلاحيات المساعدين (RBAC) والـ Middleware الصامت: كيف سيتحقق الـ middleware.ts من صلاحيات المساعد دون إرسال Database Query مع كل صورة أو تنقل؟ وكيف سنحمي جدول المدفوعات في Supabase RLS إذا كان المساعد يملك فقط صلاحية manage_exams: true؟
اختبار تفاصيل تجربة المستخدم الحرجة (iOS & Mobile UX): لماذا يقوم متصفح الآيفون بعمل Zoom عشوائي عند الضغط على خانات الكتابة وكيف سنمنعه؟ وكيف سنضمن عمل الـ Voice Note في المنتدى على الآيفون والأندرويد معاً؟ وكيف سنعالج اتجاه شريط الفيديو في موقع عربي RTL؟

انتظر تقييم المهندس المشرف لإجاباتك على هذه الأسئلة الـ 10 قبل كتابة أي كود في المشروع.
